# wego-voice

**唱的当下，就听见自己唱准了。**

Windows 桌面工具。麦克风进来的声音经过音高检测与修正后**立刻**送回耳返 ——
不是唱完再修，是唱的过程中就听到。声线也能当场换。

全程在本机跑，不联网、无账号、声音不出本机。

**[下载](https://github.com/NUDC/wego-voice/releases/latest)** ·
**[官网](https://nudc.github.io/wego-voice/)** — 免安装单文件，双击即用。

---

## 功能

### 实时音高校准

端到端实测 **29.92 ms**。超过 50 ms 会触发延迟听觉反馈效应，人会不自觉地
结巴跑调 —— 那时产品比不开更糟，所以这个数字是前提，不是性能指标。

- 按**调式**量化，不是简单吸附到最近半音
- **颤音会保留**，不会把人唱成 MIDI
- 跑调太离谱时不硬拉，避免刺耳失真
- 修正速度连续可调：从「修得不露痕迹」到「彻底电音」

### 实时声线塑形

打包成具名**角色**，选中即生效；引擎运行时拖滑杆，声音当场改变。

| 维度 | 作用 | 代价 |
|---|---|---|
| **共振峰平移** | 声道长短 → 更细 / 更粗 | 不动音高，**不增加延迟** |
| **频谱倾斜** | 整体明暗 → 更亮 / 更厚 | **不增加延迟** |
| **整体移调** | 音高整体搬移 | 超过 ±5 半音有明显金属感 |

内置 7 个角色（原声 / 少年 / 御姐 / 少女 / 童声 / 大叔 / 电音），
可改、可复制、可新建，存在 `%APPDATA%\com.wego.voice\characters.json`。

> 做得到「像另一个人」，**做不到「像某个指定的人」**。
> 不提供任何声线来源，参考素材由使用者自带；
> 取得被模拟者同意是使用者的责任。

### 从参考音频生成角色

拖一段 WAV 进来，跟你自己的干声比对，自动算出该拧多少共振峰与倾斜。

音高差会测出来但**刻意不采用** —— 参考音源比你高，不代表你该升调去唱，
那就不是这首歌了。「像另一个人」主要由共振峰承担。

### 离线重新校准

实时链路被 30 ms 捆着手脚：不能回看、f0 只能用因果算法、PSOLA 窗口被
`f0_floor` 截断。**离线重跑这三条限制一条都没有。**

- **八度纠错** —— 拿邻域中位数揪出 YIN 翻倍/减半的离群帧。实时看不到邻域，修不了
- **零相位平滑** —— 前向一遍反向一遍，滞后抵消，修正不再慢半拍
- **窗口不截断** —— 按真实周期走，低音区音质不再拿去换延迟

应用里在「**录音**」页操作：展开一条录音 + 选一个角色 → 开始。
产物放在录音旁边，命名 `<原名>-corrected.wav`，与干声**等长**，
在列表里**挂在那条干声下面**，两个播放器并排，可直接 A/B。

```bash
wego-bench recorrect --input 干声.wav --output 修好.wav --key C   # 命令行等价
```

> ⚠️ **引擎在跑时离线处理被禁用**（架构红线 3）。它满载单核，而实时链路
> 每 3 ms 就要交一次货 —— 同时跑必然爆音。不用"降低线程优先级"糊弄：
> 优先级只降低概率，不消除冲突。这条守卫由 `--selftest` 端到端验证。

合成素材实测（C4-E4-G4-E4，全部唱低 45 音分，带 ±35 音分颤音）：
四个音修到 **-0.8 / +1.0 / +12.2 / +4.7** 音分，颤音从 59 保留到 51 音分。
处理速度约 26× 实时。

> 产出的音高轨同时是 **DDSP-SVC 声线转换的必需输入** —— 那条路和这条共用它。

### 干声录制

落盘的是**原始干声**，不是耳返里那个修正过的声音。修正音有损且不可逆，
只存它等于放弃了换角色重来、离线重新校准、送进声线转换的机会。

存在「音乐 / wego-voice /」，32-bit float WAV。丢帧数在调音页的录音条上
**常驻显示** —— 悄悄丢帧比录不上更糟：拿着有断裂的素材去做后续处理，
事后根本查不出原因。

「**录音**」页管素材：听、改名、删、离线校准。删除走**回收站**而不是直接抹掉 ——
唱出来的东西删错了没有任何办法找回来。改名时配套的校准版跟着改，
否则两个文件的配对关系就断了。

### f0 准确度

`wego-bench f0` 拿**真值已知**的合成素材打分，用的是 MIR 那套指标：
RPA（±50 音分命中率）与 RCA（折叠八度后的同一指标）。
**两者之差就是八度错误** —— 混进一个总准确率里根本看不出来，
而它对音高修正是致命的。

11 段素材覆盖的是不同的**失败模式**，不是不同的旋律：长音、颤音、滑音、
男低音、女高音、八度跳进、带换气的乐句、三档信噪比、小音量。

现状：11 段全部 **RPA 100%、八度错误 0%**。

这个数是**修出来的**，不是一开始就有的。6 dB 信噪比那一段原本
RPA 只有 66.8%，24% 的帧差了整八度或十二度，而且误差**全部朝下**。
成因在 YIN 自己：CMND 的累积均值归一化让 d′ 随 tau 系统性变小，
噪声一填浅真周期处的谷，2τ / 3τ 就先跌破绝对阈值。

离线的邻域中值救不了 —— 实测错段中位数 13 帧，而中值窗口只有 ±12 帧，
中值本身就落在错的那一侧。所以修在了检测器里（`yin.rs::undo_subharmonic`），
实时与离线两条路一起受益，实时成本低于 bench 的测量噪声。

> 这也是**没有**引入神经 f0（RMVPE）的原因：它的报价是 361 MB 模型，
> 而它唯一能赢的那一档，40 行 DSP 已经补上了。

### 声线转换（神经，开发中）

「像某个指定的人」那一档。它做不进 30 ms（内容编码要看上下文），
只能放在录制之后 —— 所以入口在「录音」页，不在「调音」页。

**推理跑在一个单独的进程里**（`wego-clone.exe`），不在主程序内：

- 主程序仍是 **6.5 MB 免安装单文件**。模型（约 425 MB）与推理程序
  按需下载，不用这个功能的人一个字节都不必付
- 架构红线 3 从"一道守卫"升级成**进程级隔离** —— 推理连碰音频线程的
  机会都没有，而且子进程整体以 `BELOW_NORMAL_PRIORITY_CLASS` 起
- 它崩了主程序不跟着崩

链路：内容编码器（ContentVec，ONNX）抽出"唱的是什么"，f0 与音量另外
显式给，DDSP 解码器按目标音色重新合成。**音高走你的，音色走他的** ——
实测转换前后音高中位偏差 +0.7 音分。

推理引擎用 **tract**（纯 Rust），不需要 onnxruntime.dll。

> ⚠️ **尚未发布，音质未经验证。** 目前跑通的是管线，不是效果。
> 自动下载也还没做 —— 界面会给出模型目录，需要手动放文件。

### 噪声门

在没有人声的帧更新噪声本底，**有人声时冻结**。它解决的不是"听得到底噪"，
而是两个真症状：风扇、电流声有周期成分，会被当成人声去修；
噪声抬高非周期度，会让修音时断时续。

门关着时不跑音高检测 —— 安静时平均回调耗时从 70 µs 降到 **9 µs**。

### 诊断页

单机软件没有遥测，用户机器上出了问题我们看不见 —— 这一页是唯一的可观测性
来源，也是用户判断"自己这块声卡行不行"的地方。

延迟构成 · 实时健康度（xrun / 溢出 / 整机停顿）· 时钟漂移 ppm ·
输入噪声本底 · 往返延迟实测 · 引擎参数。

### 系统托盘

低延迟模式会**独占声卡**，运行期间系统其他声音会静音。托盘图标的颜色就是
这件事唯一持续可见的信号：灰 = 已停止，蓝 = 运行中，琥珀 = 有爆音。

关闭窗口收进托盘，**退出只能从托盘菜单**。

## 硬件要求

**需要**

- **有线耳机**，或外置声卡 / USB 麦克风
- Windows 10 / 11（x64）
- Microsoft Edge WebView2 运行时（Win11 与较新的 Win10 自带）
- 录音时能让本程序独占声卡

**做不到**

- **蓝牙耳机** —— 编解码本身就有 100~250 ms 延迟，是无线协议的物理限制，
  任何软件都绕不过
- macOS / Linux —— 低延迟路线是 Windows 特有的（WASAPI 独占）
- 手机

> ⚠️ **务必戴耳机。** 外放会让麦克风拾到自己的输出，形成啸叫回路。

## 还没做

- 基于神经网络的**离线声线转换**（「像某个指定的人」那一档）

## 构建

需要 Rust（stable，MSRV 1.80）+ Node 20+。

```bash
cd app
npm install
npm run tauri build -- --no-bundle     # 产物：target/release/wego-voice-app.exe
cargo test --release --workspace
```

> 🔴 **打包必须走 `npm run tauri build`，不能直接 `cargo build`。**
> 后者出来的 exe 前端是死的：开窗即空白、零 IPC，看起来像应用崩了。

三种入口，同一个可执行文件：

```bash
wego-voice-app.exe               # GUI
wego-voice-app.exe --autostart   # 开窗即启动引擎
wego-voice-app.exe --bench       # headless 压测，不创建 WebView
wego-voice-app.exe --selftest    # 自检
```

音频测量工具 `wego-bench`：

```bash
wego-bench devices                          # 列设备
wego-bench soak -d 600 --mute               # 10 分钟连测，查时钟漂移
wego-bench dsp -d 30 --formant-shift 4      # 离线量 DSP 成本，不碰声卡
wego-bench f0                               # f0 准确度评测（合成素材，真值已知）
wego-bench f0 --detail noisy6               # 某段素材的误差解剖
wego-bench timbre --reference 她.wav --source 我.wav
wego-bench --help
```

> ⚠️ 量 DSP 成本必须用 `dsp` 子命令。`soak` 喂的是真实麦克风 ——
> 没人唱歌时判为清音，PSOLA 直接透传，测出来的跟 DSP 真实成本无关。

官网：

```bash
cd site
npm run dev      # http://localhost:5174
npm run build    # 预渲染成零 JavaScript 的静态页
```
